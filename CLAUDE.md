# Working style

- Do the work without explanation. Explain only when asked.
- Keep token usage low: short replies, no preamble, no long recaps.
- When done, give a brief summary of what changed (1-3 short lines), plus any errors, blockers, or decisions that need the user.
- Always ask before pushing to GitHub, every time.
- Add a short tip about the project or workspace only when it would have a real impact. Skip minor ideas; most replies should have none.
- Do not restate the request or narrate steps.
- Read only the files and sections needed. Do not re-read files or re-run checks without a reason.
- Do not spawn subagents unless asked.
- Ask only when truly blocked; otherwise pick the sensible default.
